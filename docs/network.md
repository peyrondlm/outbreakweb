# Client network: emulated network adapter, gateway and configuration

Last updated: 2026-10-15 (later sections carry their own dates). Tags: **[FACT]** = verified by running it, with a log or test. **[HYPOTHESIS]** = unconfirmed.

Summary: the runtime emulates the adapter **hardware** (DEV9 + SPEED + SMAP + PHY + EEPROM), so the game's own network IRX modules run unchanged. Ethernet frames leave over WebSocket to our own gateway (Go, gVisor netstack). The gateway provides DHCP and DNS with overrides, and does NAT only toward an allowlist. The memory-card network configuration (`BWNETCNF`) is generated by our own tool, and the disc's `NETCNF.IRX` reads it correctly.

## 1. Inventory of the disc's network modules (SLUS-20765)

Extracted from the user's own disc image. Imports and exports come from the `0x41E00000`/`0x41C00000` tables of each IRX. The version is the one in the `.iopmod` header.

AVE-TCP function table (`AT_DSP_CallTable`, built by `AT_init`; names come from the debug strings) **[FACT, static]**: `0x4105` = IF UP (`ave-tcp: IF UP addr %d.%d.%d.%d mask … broadcast …`; SNIOPINT passes it `{u16 if, u16, addr, mask, bcast}`), `0x4110`/`0x4111` = TCP socket, `0x4115` = `AT_TCP_Abort`, `0x411C` = `AT_TCP_Delete`. Indices 0x4100-0x4137 are occupied according to the table. The DHCP ones are added by `AT_addDhcpApi`. The word at `avetcp_base + 0x16178` (0x38978 with AVE at 0x22800) is a debug flag: with bit 0 set, AVE prints every call.

## 2. Emulated hardware (runtime, `net` branch of the fork)

File `ps2-web-recomp/runtime/src/iop/dev9.cpp`. Active **only** if a gateway is configured (`PS2_NET=ws://…` or `--net`). Without that, all addresses go to the generic map as before and DEV9.IRX keeps saying "unknown dev9 hardware".

| Block | Addresses (IOP physical) | Behavior |
|---|---|---|
| DEV9 (bridge) | `0x1F801460-0x1F80147F` | `0x146E` = **0x32** (CXD9611, expansion bay). `0x1462` = 0 (device present). The rest (power `0x146C`, `0x1464/66/60/74/7E`) is stored and returned |
| SPEED | `0x10000000-0x100000FF` | rev `+0x02` = **0x11** (ES2), caps `+0x04` = SMAP only (no ATA), `+0x20` = 1 (official adapter). INTR_STAT `+0x28` / INTR_MASK `+0x2A`: IRQ 13 when `cause & mask`. DMA_CTRL `+0x24` (bit 0 = SMAP). PIO `+0x2C/+0x2E` wired to the EEPROM |
| EEPROM 93C46 | PIO bits 7=CS, 6=SK, 5=DI, 4=DO | Microwire state machine (start, opcode READ=10, 6 address bits, bit 0 padding, words MSB first, sequential read). Words 0-2 = MAC (LE), word 3 = 16-bit sum (SMAP.IRX verifies it) |
| SMAP FIFOs | `+0x1000..0x1040` (TX ctrl/wr_ptr/frame_inc, RX ctrl/rd_ptr/frame_dec), data `+0x1100`/`+0x1200` | 16 KiB FIFOs, self-clearing reset, 32-bit PIO or DMA (ch 8, with `TXFIFO/RXFIFO_DMAEN`) |
| EMAC3 | `+0x2000..0x206F` | 32-bit registers in two 16-bit halves (the high one at the low address). Applied on writing the low half. MODE0: self-clearing soft reset + IDLE bits. TxMODE0 GNP_0 -> transmit. STA_CTRL -> PHY |
| PHY DP83846A | via STA_CTRL | ID 0x2000/0x5C21, BMCR 0x3100, BMSR 0x7809 + LINK + AN complete, ANAR 0x05E1, ANLPAR 0x45E1, PHYSTS = 100 Mb/s FD |
| BD | TX `+0x3000`, RX `+0x3200`, 64 each | `BD_MODE` bit 0 = byteswap (DEV9's driver enables it). TX: ctrl READY 0x8000, length, pointer (FIFO + 0x1000). RX: EMPTY 0x8000, pointer = 0x4000 + start |
| Interrupts | SPEED causes | TXEND+TXDNV when a TX finishes. RXEND per received frame. RXDNV if no free BD. PHY/EMAC loopback: what is transmitted returns to RX (DEV9.IRX's self-test sends a 1514 B frame and waits for RXEND+TXEND+TXDNV) |
| Network polling | IOP job `kJobDev9Poll` every 250 us | Takes frames from the backend and delivers them while there are free RX BDs (queue of up to 256). Frames under 60 B are padded |

Also:
- `runtime/src/iop/iodev.cpp`: the HLE ioman accepts `AddDrv`/`DelDrv` and redirects open/read/…/dopen/dread/devctl of those devices to the guest driver's operations table. It is done as a *tail call* on the calling thread, so blocking operations, such as MCMAN's, work. Enabled with `PS2_NET` or `PS2_IODEV=1`. Without it, DEV9.IRX unloads (AddDrv failed) and NETCNF cannot read `mc0:`.
- `libs.cpp`: `ReferModuleStatus` now fills `ModuleStatus` as in the SDK (`.iopmod` name, `version` at +0x38, `id` at +0x3C). SMAP.IRX uses it to require `dev9` >= 2.4.
- Backend (`runtime/src/net/`): `net::Backend` interface (non-blocking send/receive). Implementations: `websocket_native.cpp` (ws:// client with POSIX sockets, reader thread and reconnection) and `websocket_web.cpp` (Emscripten WebSocket API, linked with `-lwebsocket.js`, accepts wss://). One frame per binary message, like the v86 relay.
- Variables: `PS2_NET` (URL), `PS2_NET_MAC` (default `00:04:1f:52:45:4f`), `PS2_NET_PCAP` (pcap of everything entering and leaving the adapter), `PS2_NET_TRACE=1` (PHY log and every frame).
- Pending: DEV9 state is not part of save states.

## 3. Gateway (`net/gateway`, Go 1.27 + gVisor netstack)

- `GET ws://host:8765/eth[?token=…]`: one session = one gVisor stack of its own (total isolation between sessions).
- Virtual network: router/DHCP/DNS at `10.0.2.2`, guest at `10.0.2.15/24`, router MAC `52:55:0a:00:02:02`.
- ARP is resolved by the gateway, not gVisor: proxy ARP for everything except the guest's IP, so conflict probes get no reply. The guest's neighbor is learned statically.
- DHCP (DISCOVER/REQUEST/INFORM -> OFFER/ACK/NAK, BOOTP >= 300 B, broadcast) and DNS are built at the frame level. DNS answers only from the overrides table (`*.reo.capcom.sf.yav4.com` -> 198.18.0.10, `*.dnas.playstation.org` -> 198.18.0.20); everything else is NXDOMAIN. The service IPs are outside the subnet, so the guest reaches them through the router.
- NAT: gVisor TCP/UDP forwarders (promiscuous mode + spoofing). It connects **only** if `(proto, dst ip:port)` matches an `allow` rule -> `upstream host:port`. Anything else gets RST. It is not an open proxy.
- Limits: total and per-IP sessions, tokens, origins (browser), frames/s and bytes/s (token bucket), concurrent flows per session, idle timeout, max frame 1518 and a single MAC per session. Anti-spoof: only source IP = the leased IP is accepted.
- `-pcap DIR`: one pcap per session.
- JSON config (`config.example.json`, `-print-config`).
- Tests (`go test ./...`, also with `-race`): DHCP (OFFER with mask/router/DNS, ACK, NAK), ARP (does not answer probes), DNS (overrides with uppercase and wildcard, NXDOMAIN, malicious suffix), allowed TCP handshake + RST to a disallowed destination/port, a **second gVisor stack acting as the PS2** (DHCP + real TCP to 198.18.0.10:8300 up to an echo server, 12-byte lobby header round trip, connection outside the allowlist rejected), limits (429/403) and rule matching. (Local evidence, not published.)

## 4. Network configuration on the memory card ("Your Network Configuration")

**[FACT]** Format, read from the disc's NETCNF.IRX v1.20 (disassembled) and from ps2sdk's reimplementation:
- `mc0:/BWNETCNF/BWNETCNF`: plain-text index, one line per entry: `type,flag,file,name`. Type 0 = combination (`netNNN.cnf`, plain text), 1 = provider/interface (`ifcNNN.dat`), 2 = device (`devNNN.dat`).
- `net000.cnf`: `interface "Combination1" "ifc000.dat" "dev000.dat"`.
- `ifc000.dat`: `type eth` + `dhcp` (or `-dhcp`, `address`, `netmask`, `route add -net 0.0.0.0 gw … netmask 0.0.0.0`, `nameserver add …`).
- `dev000.dat`: `type eth`, `vendor "SCE"`, `product "Ethernet (Network Adaptor)"` (must match what SMAP registers), `phy_config auto`.
- All start with `# <Sony Computer Entertainment Inc.>`.
- The `.dat` files are obfuscated with the console's **i.LINK ID** (`sceCdRI`). Each 16-bit LE word is stored as `rotl16(w, k) ^ 0xFFFF`, and a trailing odd byte as `rotl8 ^ 0xFF`. `k` runs through 24 values derived from the 8 ID bytes: `(b>>5)+1, ((b>>2)&7)+1, (b&3)+1`. The table is at `0x2B1F0` of the module loaded at 0x20000. The runtime's `sceCdRI` returns an all-zero ID (k = 1 always), so configurations from a real PS2 do **not** work as-is.
- Icons: `icon.sys` and `SYS_NET.ICO` (from the disc, `NTGUI2/CONF/ENGLISH/`).

Tool: `net/gateway/tools/ps2netcnf.py`:
- `install CARD.ps2 --icons …/NTGUI2/CONF/ENGLISH [--static IP/24,GW,DNS]`: formats if needed and adds `BWNETCNF`.
- It also has `files`, `ls`, `cat --decode` and `decode`.
- The 8 MiB image carries spare data with ECC. The ECC table matches MCMAN's byte for byte (test).

**Validation [FACT]**: in the emulated IOP, with the disc's IRX files (`NTGUI2/MODULES/SIO2MAN.IRX` + `MCMAN.IRX` + `IOP/MODULES/NETCNF.IRX`), a test IRX (`scripts/iop_mctest.py`) reads the index through ioman, lists the directory and calls `sceNetCnfLoadEntry("mc0:", 0, "Combination1")`. Result: `-> 0 (file_err 0, syntax_err 0)`, `ifc type 1 dhcp 1`, `dev vendor "SCE" product "Ethernet (Network Adaptor)"`.

## 8. Network ready to use (2026-10-16, `outbreak` branch of `ps2-web-recomp`)
- **Automatic BWNETCNF [FACT, native]:** `runtime/src/iop/netcnf_card.cpp` (C++ port of `tools/ps2netcnf.py`). When the card is mounted (`sio2.cpp`, `load_card`), if the network is enabled (`PS2_NET`/`--net`; on the web always unless `?nonet`) and `mc0:/BWNETCNF` does not exist, it creates it with the "REO gateway (DHCP)" entry (`ifc000.dat` dhcp, `dev000.dat` SCE/"Ethernet (Network Adaptor)", obfuscated with a zero i.LINK ID) and the disc's icons (`NTGUI2/CONF/ENGLISH/ICON.SYS`, `SYS_NET.ICO`).
  - It does not overwrite saves: it only uses free FAT clusters, checks space before writing and recomputes the ECC of touched pages. A blank card (page 0 all 0xFF) is formatted first; a corrupt card or one with odd geometry is left alone. If `BWNETCNF` already exists (e.g. created with the wizard) nothing changes.
  - `PS2_NET_CARD=0` disables it. It marks the card dirty, so it is saved to disk or IndexedDB.
  - Tests: new card -> `ps2netcnf.py ls` shows the 6 files, 0 pages with bad ECC, and `ifc000.dat` decodes to `type eth / dhcp`. On a card with the `BASLUS-20765NET` save and no BWNETCNF, it is added and the save stays intact. On a card that already has BWNETCNF, it is untouched.
- **DNAS patches in the pipeline:** `scripts/patches/SLUS-20765.txt` (versioned). It only holds addresses and our own bypass instructions (`sb zero,0(a0); addiu v0,zero,1; jr ra; nop`), with no game bytes.
  - `scripts/translate.sh <game>` gathers entries, modules, overlays and patches (`games/<game>/patches.txt` takes priority; otherwise `scripts/patches/<serial>.txt`, with the serial taken from SYSTEM.CNF) and rebuilds `build/tools/eerecomp` if stale.
  - `port.sh` uses it on every translation. `build_web.sh` calls it with `--if-patches-changed`: it re-translates only if `generated/<game>/patches.applied` differs.
  - outbreak1's `entries.txt` gained the network entries (netwk/netdnas/submain).
- **Web:** `web/shell.html` sets `PS2_NET = ?gateway=` or, by default, `ws://<page host>:8765/eth` (`?nonet` unplugs it). The PHY always reports link. If the gateway does not answer, only online mode fails (DHCP without reply) and offline stays the same.
  - `websocket_web.cpp` retries every >= 3 s while the game sends frames, so it also works if the gateway comes up after the page is opened. It logs "cannot reach …, the game stays offline" once.
  - The gateway needs `origin_patterns` with `localhost:8620` and `127.0.0.1:8620`. Without that, coder/websocket rejects the browser's Origin. `run-local.sh` configures it.
- **One command:** `run-local.sh` starts the US server (`server/tools/usapp.py`, :10127), the gateway (:8765, generated config with allowlist 10127/8300/8690 and per-session pcaps) and `serve.py` (:8620). It waits for the 3 ports to answer and stops them with Ctrl+C. Configurable with `GW_PORT`, `WEB_PORT`, `APP_PORT`, `SERVER_CMD` and `LOGS`.
- **Native verification [FACT]:** new card + `--net` (run-local.sh on alternate ports), with the inputs of §7. The game asks "No NET file… create?" -> NO, and goes straight to "Select Network Configuration" with "1. REO gateway (DHCP)" (HARDWARE: SCE/Ethernet), **without the wizard**. Then come the DNAS screen and DHCP -> DNS app01 -> **TCP to 198.18.0.10:10127** with a frame exchange and then a DNS lookup of `snap01`. Commit `88a2cad` on `outbreak`.
- **run-local.sh [FACT]:** starts the 3 processes on the default ports. They answer from WSL and from Windows (8620 -> HTTP 200 with `PS2_NET` in the page; 8765 -> 101 with Origin `http://localhost:8620` and 403 with another origin; 10127 open) and are stopped with SIGTERM/Ctrl+C.

## 14. Per-game delay: the `REOGW-RTT` notice (2026-10-24; gateway `f51371a`/`dba4fbd`/`9f9e76a`, server `4cf7aba`)
- **What [FACT]:** after each WebSocket ping (every 15 s) the gateway writes into **every open UDP flow** of that session the datagram `"REOGW-RTT"` + u32 BE ms (the browser <-> gateway RTT, including any proxy); also once when a flow opens if an RTT is already measured. It is not a kk datagram (no trailer): the other services ignore it, like `REOGW-BYE`.
- **Server [FACT]:** `KkService` stores the last RTT per address (it arrives before login) and, in a started room, per member `{samples, sum, max, sum of |change|}` (the first sample = the last RTT before the first 0x0F). It only affects the session of that exact address (like BYE). `game X stats after …` now adds `name rtt N ms (max M, jitter J, K samples)` and `; one-way est. worst pair N ms, max jitter J ms` (one-way ≈ `(rtt_a + rtt_b)/2` of the two highest average RTTs; everything goes through the relay). Metrics: counters `lag_n`/`lag_ms` (sum)/`lag_b` (buckets `<50`, `50-100`, `100-150`, `150-250`, `>250 ms`) and an event `{"t":"game_lag","game","players","oneway","rtt_max","jitter","dur"}` in `events-*.jsonl`.
- **Why the gateway and not the page:** the gateway already measured the RTT and it is the same in all browsers; it does not depend on the new page being loaded or the main thread being free (browsers answer the ping at the network layer), and the server associates it with the game without crossing identifiers.
- **Limits:** 1 sample every 15 s (jitter is the variation between 15 s samples, not per-packet jitter); it measures the WebSocket, not the game loop. Games shorter than 15 s have only the initial sample.
- **Tests [FACT]:** `go test` (`TestRTTNotice`, `TestRTTNoticeEndToEnd`: guest UDP flow -> the upstream receives `REOGW-RTT` after a ping); `server/tools/kklag.py` against `tests/KkLocal.java`: `lga rtt 40 ms (max 50, jitter 20, 2 samples), lgb rtt 190 ms (max 210, jitter 40, 2 samples); one-way est. worst pair 115 ms, max jitter 40 ms`. No run with the game (the notice does not touch the guest).
- **Gateway and relay delays [FACT, measured]:** gateway p50 0.12 ms / p99 <= 2 ms (`TestUDPRelayDelay`); kk relay p50 0.6 ms. Nothing to fix there.

The mark is not cleared, so if the check runs late (state 7) it still drops it on return. It is cancelled if the game already dropped someone on its own while waiting (`+0xF` decreases). The table is only used if the three loads of the check are present (`lbu +0x4C`, `lwc1` of the clock and of the timeout). Logs: `teammate gone, looking for its slot (N players)`, `teammate gone: slot S (silent X s) marked …; others: slot i Y s`, `the game dropped a teammate (N -> M players, clock C s)`, and if none is found: `no slot silent for 20 s, left to the 300 s timeout`.

- **Killing with PS2_POKE [FACT]:**
  - Health: the public US cheat "Infinite Health" `0x4A6174 = 08FC08FC` gives u16 HP and u16 max HP of the slot-0 character. The stride between slots is **0x10E0** (in two test runs the three characters at `0x4A6174`, `0x4A7254`, `0x4A8334`: max 2300, 3000 and 1800).
  - Virus: u32 at `+0x668` (`0x4A67DC` for slot 0, also from the public cheat).
  - Setting the virus to `0x00200000` zombifies: offline "YOU DIED" appears and online the results screen `DEAD 1/3` with EXIT(SAVE). It has to be done in your own slot: poking another's slot does nothing.
  - Setting HP to 0 does not kill: the character crawls and keeps playing (virus at 75%).
- **Before [FACT]:** after dying, the dead host **stops sending game data**: its server-side relays drop from ~100 to 12 per interval. The others drop it only at the 300 s timeout: one did so at 478.5 s of clock and migrated then. About 5 minutes without a host: the "nobody picks anything up".
- **Death signal [FACT, dumps]:** byte `+0x663` of your own character (`0x4A67D7 + 0x10E0*slot`) is **0x12** when dead or zombified (offline, online, and a character killed by zombies) and **0x00** when alive, also when downed with HP 0. Byte `+0x65F` has bit 0x08 on your own character while alive (it blinks, and on death becomes 0x40). Note: the first attempt read `+0x667`, which is the float 1.0, so the signal never fired.
- **Runtime (`system.cpp`):**
  - With netaq resident, 2 or more players and your own character seen alive, 60 frames with `+0x663 & 0x10` send **once** `{"type":"left-scenario","slot":me}` over the WebSocket (`net::send_control`, new `Backend::send_text`, native and web).
  - `kk-peer-left` marks that slot immediately, with log `teammate in slot N left the scenario: marked …`.
  - `PS2_LEFT_TRACE=1` logs the fields every 600 frames.
- **Run Z9 [FACT]** (3 native File #1, host killed with the virus poke at frame 27500):
  - host: `own player out of the scenario (dead, slot 0, host, clock 120.5 s): told the gateway`.
  - Gateway: `runtime: own player left the scenario (slot 0)`.
  - Server: `host … left the scenario … told 2, its game data no longer relayed`.
  - b: `marked (clock 112.1 s)` -> `host flag 1` -> `drop (3 -> 2)` -> `latch 1` with the clock at **112.2 s**. c marks at 114.7 s.
  - That same wall-clock second, the new host takes authority. Before it was about 300 s.
  - Later c died to zombies (no poke): `own player out … slot 2` -> b drops it (`2 -> 1`). The signal also works for a natural death.
- **The one who died [FACT, Z9 + Z10]:**
  - Their game continues: results `DEAD`, EXIT(SAVE), "No system data… Create?" and "OK to quit without saving?".
  - It does not hang because the others dropped it, and the server does not repeat the notice (goneTold).
  - With X alone, the script falls into a loop between the two save dialogs, because the cursor stays on NO.
  - **Z10** (2 native, left/X alternating): the host dies and sends the notice. b marks the slot at 113.0 s and migrates at 113.1 s (latch 1). The host goes through EXIT and the server says it is back in the waiting room (1 still in game), with no second notice. The final capture of the host is the **MEETING ROOM** with the log "Infection rate 100% / zombified. Died.": it returns to the room correctly.
- **Not tested:**
  - Picking up an item: no route to one. The indicator is "I am host" + the netaq latch (§16).
  - The production wasm.
- **File #2 [FACT, runtime `1079e1a`]:**
  - The struct is the same, but the flags are 0x1C bytes further on. On the offline Wild Things route, Kevin, Mark and Jim are at `0x4C6350`, `0x4C7450` and `0x4C8550` (stride 0x1100; u16 HP and u16 max HP). The float 1.0 is at `+0x680`, the virus at `+0x684` and the death byte at **`+0x67F`**.
  - With the virus at 0x200000 that byte becomes 0x12 and health 0.
  - File #2 has no control of the "own" bit: the equivalent byte (`+0x67B`) was not 0x08 online. It is still bounded by the max-health range, the resident netaq and the table with 2 or more players.
  - **Y2** (2 native, File #2, host killed at frame 27000): the host: `own player out … (dead, slot 0, host, clock 191.6 s)`; server: `host … left the scenario … told 1`; b: `marked (clock 188.3 s)` -> `drop (2 -> 1)` -> `host flag 1` -> `latch 1` at **188.4 s**.
  - Before the results screen, the dead player in File #2 stays a good while in the 3D view. EXIT in File #2 was not tested: the host's run ended first.

## 18. Teammates stuttering: the game's send interval (2026-11-03; runtime `420194b`)
- The game sends its character data (reliable 0x0F) only when a game-time accumulator reaches a float in the ELF: File #1 1.0 s (`0x235F60`), File #2 0.5 s (`0x2412A0`); the remote character walks to the last data point and stops. It is not the gateway or the relay (0.2-0.5 ms measured) nor DEV9/SMAP. `online_flush_interval()` sets it to 0.0 at startup; `PS2_NET_FLUSH=<s>|orig`. Details and runs ST1-ST3: [stutter.md](stutter.md).

## 19. Tracker data between pages (2026-11-03; gateway `e04f749`, server `beb9a41`, page on outbreak)
- New page WebSocket text `{"type":"trk",...}` -> `REOGW-TRK` (gateway, at most 1 per 400 ms per WebSocket) -> `kk-peer-trk` to those in the same game. It is handled by the page (it wraps the `WebSocket` constructor and takes the runtime's), not by the runtime. Format: [protocol.md §6.18](protocol.md); tests: [tracker.md](tracker.md).
